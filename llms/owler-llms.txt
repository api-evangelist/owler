# Owler

> Owler is a crowdsourced competitive- and business-intelligence platform covering more than 20
> million public and private companies and 45M+ competitive relationships contributed by a
> community of 5M+ business professionals. The Owler Enterprise API exposes that graph as six
> read-only REST operations across three products: Company Premium (firmographics, funding,
> acquisitions, CEO, stock), Competitor Premium (the scored competitor list) and Feed (company news
> and business events). Owler was acquired by Meltwater in 2021.

Generated by the API Evangelist enrichment pipeline on 2026-08-14 from Owler's published OpenAPI
3.0.1 definition and live probes. Owler does not publish an llms.txt of its own — /llms.txt was
probed on apiv2.owler.com, developers.owler.com, developers-v3.owler.com, corp.owler.com and
www.owler.com on 2026-08-14 and returned no document on any of them.

## API

- [Owler Enterprise API](https://developers.owler.com/): Swagger UI developer portal for the v3
  API. Base URL https://apiv2.owler.com. Six GET operations, no write path.
- [OpenAPI 3.0.1 definition](https://developers-v3.owler.com/apis/api3-swagger.json): the machine-
  readable contract the portal renders.

### Authentication

A per-account API key sent in the `x-api-key` request header. There is no OAuth, no scopes and no
self-serve signup — keys are issued through the data-licensing sales process. A missing, invalid or
unentitled key all return `403 Authentication Failed`; there is no 401 in the contract.

### Operations

- `getCompanyByWebsite` — GET /v1/companypremium/url/{website} — full company record by domain.
- `getCompanyById` — GET /v1/companypremium/id/{companyId} — full company record by Owler id.
- `getCompetitorsForWebsite` — GET /v1/company/competitorpremium/url/{website} — scored competitors
  by domain.
- `getCompetitorsForId` — GET /v1/company/competitorpremium/id/{companyId} — scored competitors by
  Owler id.
- `getFeedsByWebsite` — GET /v1/feed/url — news and events for up to 10 domains.
- `getFeeds` — GET /v1/feed — news and events for up to 10 Owler company ids.

### Conventions an agent must know

- Response format is chosen with a `?format=json|xml` QUERY PARAMETER, not an Accept header. Use
  json; the xml shape is undocumented.
- Pagination is an opaque `pagination_id` cursor — but the first-page sentinel differs by product:
  send `*` on the competitor operations and a BLANK value on the feed operations.
- The feed operations accept at most 10 comma-separated identifiers and return 10 results by
  default, 100 maximum (`limit`).
- Company and competitor lookups are one company per request. Enriching N companies costs N calls.
- 429 Too Many Requests is declared on every operation, but Owler publishes no limit, no window and
  no Retry-After. Back off exponentially with jitter.
- Error bodies have no documented schema on any status. Trust the status code, parse the body
  defensively.
- All six operations are GETs, so retries are safe. There is no idempotency-key mechanism because
  there is no write path.

## What Owler does not publish

Recorded so an agent does not go looking: no SDKs or CLI in any language, no GitHub organization,
no MCP server, no A2A agent card, no webhooks or AsyncAPI, no /.well-known/ documents of any kind,
no security.txt, no trust center or certification page, no changelog, no deprecation policy, no
SLA, no sandbox or test credentials, and no published rate limit. The previous API generation
(api.owler.com, 13 operations including company SEARCH) was retired without notice and its host no
longer completes a TLS handshake.
